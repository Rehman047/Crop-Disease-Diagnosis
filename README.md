# AgroSense: multimodal crop disease diagnosis (AI341 semester project)

Question: does fusing a leaf photo with a short text note beat image-only classification, especially under
domain shift (lab photos -> real field photos)? **This repo currently contains Phase 1 only**: data pipeline +
image-only EfficientNet-B0 baseline, evaluated on an in-distribution (ID) test set and a shifted test set.

> **AI-use disclosure:** the code in this repository was written with the assistance of an AI coding tool (Claude).
> The author has reviewed it and is responsible for being able to explain every part.

## Layout
```
configs/baseline.yaml     all settings (paths, split, model, loss, training, eval, high-cost classes, smoke)
src/data.py               dataset discovery, class intersection, near-duplicate grouping, split, transforms, analysis plots
src/model.py              EfficientNet-B0 classifier -> (logits, features); param count; latency
src/train.py              loss factory (ce_weighted | focal | ce_label_smoothing), AdamW, AMP, early stopping
src/evaluate.py           metrics, ECE, reliability diagram, confusion matrix, guarded + logged shifted-set evaluation
src/utils.py              seeding, config, paths
notebooks/01_data_baseline.ipynb   thin driver for the whole phase
results/                  generated by real runs only (git-ignored)
```

## Rules the code enforces
* **PlantDoc is never used for training, early stopping or tuning.** `train.py` never imports PlantDoc code; the only
  function that loads PlantDoc images for scoring is `evaluate.evaluate_shifted`, which requires a checkpoint that was
  already chosen on ID-validation macro F1 and appends every call to `results/shifted_access_log.csv`.
  (Seeing it is hard to do *accidentally*; it cannot stop a person who edits the code on purpose.)
* **Split without leakage:** perceptual-hash near-duplicate groups (incl. rotated/flipped copies) stay in one partition;
  per-class stratified 70/15/15; the split uses its own `split_seed` so all training seeds share one split; lists saved to `results/splits/`.
* **No invented numbers:** metrics only come from `results/.../metrics.json` written by real runs.

## Reproducibility
Fixed seeds (python/numpy/torch, cuDNN deterministic), config saved with every run (`config_used.json`, hash stored in
`metrics.json`), pinned `requirements.txt`. GPU + AMP can still differ in the last decimals; the 3-seed std measures that.
Each run lands in `results/runs/<experiment>/seed_<n>/` (best.pt, training_curve.csv, train_summary.json, metrics.json, plots).
